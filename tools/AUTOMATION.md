# Автоматический выпуск перевода под новую Orca

Инструкция для агента, которого Orca запускает по расписанию в этом репозитории.
Выполнять целиком, шаг за шагом, из корня этого репозитория.
Все механические действия делает `tools/release.py`; агент только переводит
и пишет запись в CHANGELOG. Ничего, кроме описанного ниже, не делать: не менять
код скриптов, не трогать чужие файлы, не делать force-push, не создавать ветки.

## 1. Снять строки и посмотреть, что изменилось

```sh
python3 tools/release.py check
```

Скрипт печатает отчёт приёмки, список ключей с изменившимся текстом,
новые ключи с `count` без форм числа и непокрытые строки с их ключами.

- Если написано «ВЫПУСКАТЬ НЕЧЕГО» — эта версия Orca уже выпущена
  (так бывает при ручном запуске без новой версии). Остановиться, шаг 5.
- Если написано «перевод не нужен» — сразу шаг 4 с темой
  `версионный релиз без изменений перевода`.
- Если «НУЖЕН ПЕРЕВОД: N строк» — шаги 2 и 3.
- Если `check` завершился ошибкой (extract.py или build.py упали, формат
  отчёта изменился) — остановиться и описать ошибку. Ничего не публиковать.

## 2. Перевести

Создать файл `tools/dict/stageN.json` (номер N скрипт назвал в выводе),
плоский JSON `"английский текст": "перевод"` для всех непокрытых строк.

Правила:

- Глоссарий: workspace → рабочая область, worktree не переводится,
  runtime → среда выполнения, session → сессия, pull request → пул-реквест,
  review → ревью, quick command → быстрая команда, workflow → сценарий,
  thread → тред, subagent → субагент, Orca — женского рода («Orca не смогла»).
  Полный список — раздел «Глоссарий» в README.md.
- Смотреть на ключи, а не только на текст: короткое слово в разных ключах
  может значить разное. Если один текст живёт в разных смыслах, перевод
  задаётся по ключу в `tools/dict/by-key.json` (`null` = оставить английским).
- Ключевые слова поиска по настройкам (`…search.…`, короткие строчные слова)
  переводятся: по ним ищут по-русски.
- Технические литералы (команды, пути, `ORCA_*`, имена продуктов и агентов,
  коды выхода вроде `exit {{value0}}`) переводятся тождественно, сами в себя.
- Все плейсхолдеры `{{…}}` сохраняются как есть.
- Счётчики: если английский текст сам выбирает форму (`1 file` / `{{value0}} files`,
  ключи `…One` / `…Many`), переводить обе строки, множественное — через
  двоеточие: «файлов: {{value0}}». Если ключ назван в выводе `check` среди
  «новых ключей с count без форм числа», добавить в `tools/dict/plurals.json`
  запись с формами `one`, `few`, `many`, `other` (`other` = `few`), сохранив
  плейсхолдер `{{count}}`.
- Стиль существующих переводов важнее буквальности: перед тем как переводить
  строку с новым термином, поискать термин в `tools/dict/*.json`.

Затем:

```sh
python3 tools/release.py build
```

Повторять правку словаря и `build`, пока скрипт не скажет «приёмка пройдена».
Если приёмка не проходит по причине, которую перевод не лечит (изменилось
число защищённых ключей, разрешённых путей, значений сверх лимита, extract.py
не видит ключей с count) — остановиться и описать. Не публиковать.

## 3. Описать, что появилось

Записать в `tools/CHANGELOG_ENTRY.md` от трёх до шести пунктов в стиле
записей `CHANGELOG.md`: сначала крупные темы жирным («- **Тема** — что именно
появилось, с примерами переведённых строк в кавычках»), потом одна строка
с мелочами через запятую. Числа (сколько строк, сколько ключей) не писать —
скрипт подставит сам. Строку про защищённую зону не писать — её добавит скрипт.

## 4. Опубликовать

```sh
python3 tools/release.py publish --theme "<короткая тема релиза для заголовка>"
```

Тема — три-шесть слов о главном в версии, например
`фоновые задачи в чате и состояния агентов`. Скрипт сам обновит README,
UNTRANSLATED.md, CHANGELOG.md, манифест, сделает коммит и тег, запушит,
создаст релиз на GitHub, переключит индекс маркетплейса и заявку PR #6.

Если `publish` отказался (версия на диске сменилась посреди работы,
приёмка не прошла, в рабочем дереве посторонние изменения) — не обходить
отказ, а остановиться и описать причину. Если Orca обновилась посреди
работы, повторить с шага 1: словари уже написаны, второй проход короткий.

## 5. Отчёт

В конце — пять строк: версия, сколько строк переведено из скольких, сколько
новых ключей, ссылка на релиз, что потребовало решения (спорные переводы).
Если ничего не публиковалось — почему.
